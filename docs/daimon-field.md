## Local responsibilities

Preserve native conversation/topic ownership, ordinary steering and durable human
requests while linking a chosen Nexus context through an actual Telegram Mini App.
Existing work: [#30](https://github.com/AlterMundi/telecodex/issues/30),
[#43](https://github.com/AlterMundi/telecodex/issues/43); reference investigation
[#20](https://github.com/AlterMundi/telecodex/issues/20) retains its distinct scope.
Attachment delivery [#29](https://github.com/AlterMundi/telecodex/issues/29) is closed;
real audio receipt does not qualify every source/delivery route.

Return actual selected contributions to the right session with evidence and
observed delivery. Telegram identity is not automatically Matrix identity. Keep
initData validation and application permissions; a local host must authenticate
through its own real adapter rather than forge Telegram credentials.

A future autonomous LAN conversation host is a research horizon. Telegram's open
client/TDLib or a local Bot API server does not by itself supply an offline Telegram
network or arbitrary Mini App compatibility. The canonical research compares
bounded host adapters and inspected server forks. No bot consumer, native runtime,
network deployment or maintainer-session code changes follow from this pointer.
